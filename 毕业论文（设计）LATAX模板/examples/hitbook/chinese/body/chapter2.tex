\chapter{FSDP通信瓶颈分析与实验验证}

\section{FSDP分布式训练框架概述}

从 FSDP 分布式训练框架的实现机理上看，FSDP 通过将模型划分为若
干 FSDP 实例——即图 2-1 中的 instance，并在每个实例内部对参数、梯度
和优化器状态进行按 rank 维度的完全分片。如图~\ref{fig:fsdp-train-workflow}所示，FSDP 的完整训
练流程包含以下关键阶段。在前向传播阶段，首先从本地或 CPU 加载模型
分片到 GPU 显存，若启用 CPU offload 则从 CPU 加载，然后各 rank 通
过 All-Gather 通信收集完整参数，构建完整的 FSDP 实例，在完整参数上
执行前向计算，计算完成后立即释放除本 rank 分片以外的参数副本，仅保
留当前激活单元的显存占用。在反向传播阶段，再次通过 All-Gather 恢复完
整参数，执行局部反向传播，完成局部反向后立即启动 Reduce-Scatter，对
梯度进行规约并重新切分，最终仅保留本 rank 的梯度分片，然后释放完整
参数副本。在优化器更新阶段，在分片空间内执行本地优化器更新，若启用
CPU offload 则将梯度 offload 到 CPU。

这一“分片‑聚合‑释放”的工作模式既实现了显存占用与“分片后的
模型大小 + 当前激活单元大小”近似线性相关，显著降低了单设备显存压力，
同时也自然暴露出前向与反向阶段的 All-Gather 通信，以及反向阶段的
Reduce-Scatter 通信所带来的时间开销。其中，All-Gather 主要发生在参数获
取阶段，可以通过预取 pre-fetch 机制与后续计算进行部分重叠，从而一定
程度上掩盖其通信延迟；而 Reduce-Scatter 位于反向传播的关键路径上，通
常在梯度计算完成后立即启动，属于完全阻塞的通信操作，其对整体训练性
能的影响更为显著。

本章旨在通过构建单卡与双卡大模型训练对比实验，利用 PyTorch
Profiler 性能分析工具，对基于 FSDP 的分布式训练过程中的通信开销进行
量化与分析。主要目标有三：一是识别计算与通信重叠机制下的通信瓶颈，
二是量化通信操作对端到端训练性能的影响，三是验证将 Reduce-Scatter
操作作为通信压缩优化关键路径的可行性。

\section{实验设置}

为确保性能数据的可比性与实验结论的统计可靠性，本研究采用控制变
量法设计实验。通过固定模型架构、训练数据集、超参数配置及硬件环境等
所有非实验变量，仅调整并行计算节点的规模（world size），实现通信开销
的有效隔离与精确观测。实验对照组设计如下：

\textbf{基准组：}配置单机单卡训练环境，world size 取 1。该配置不包含跨设备
通信开销，其性能数据作为纯计算性能的参照基准，用于量化分布式训练引
入的额外通信成本。

\textbf{实验组：}配置双机双卡训练环境，world size 取 2，并
启用 FSDP 全分片策略。该配置包含完整的梯度归约 Reduce-Scatter 与参数
广播 All-Gather 通信原语，用于模拟分布式训练中的典型通信行为。

\section{通信开销的定量分析}

基于 Profiler 采集的 Trace 数据，本研究对单个训练步内的计算流与通
信流进行了细粒度的离线统计与分析。图 2-2 直观展示了单卡基准与双卡实
验场景下，GPT-2 不同模型大小下的平均单步训练耗时（Step Time）的构成
对比。

\subsection{单卡与双卡训练耗时对比}

\begin{figure}[htbp]
\centering
\includegraphics[width=0.85\textwidth]{fig6}
\caption{不同规模下单卡与双卡耗时对比}
\label{fig:step-time-compare}
\end{figure}

从图~\ref{fig:step-time-compare}可以看出，双卡训练的平均 Step
耗时显著高于单卡基准，且该增量主要来源于通信开销。该图基于三个模型规模的 Profiler 汇总数据，
采用单步耗时的均值进行刻画，图中每个模型规模均给出单卡与双卡两组堆
叠柱，柱内标注计算与通信的时间占比。在单卡训练配置下，各模型规模的通信时间占比均处于极低水平，说明
单步耗时主要由计算操作与本地 I/O 开销主导。而在双卡训练场景中，跨卡
通信开销随模型规模增大呈现明显放大趋势：GPT2-small 模型中双卡单步耗
时较单卡增加约 50\%，其中通信占比达 50.5\%；GPT2-medium 模型中双卡
耗时增量进一步扩大，通信占比提升至 52.0\%；GPT2-large 模型中双卡单步耗
时较单卡增加超过 100\%，通信占比高达 61.2\%。这说明随着模型参数规模增长，
双卡训练中跨卡通信的相对开销显著提升，已成为制约分布式训练性能的关键因素。

此外，单卡训练的单步耗时随模型规模近似线性增长，这说明
模型规模扩大主要增加了计算操作的执行时间。双卡训练相对于单卡的额外开销几乎完全来源于跨卡通信
段，且通信时间占比随模型规模增大而持续升高，在 GPT2-large 模型中通
信开销已成为端到端耗时的主要增量来源。因此从工程优化的角度出发，
上述数据说明了通信压缩在大规模分布式训练中的必要性。

\subsection{通信算子分解与重叠分析}

\begin{figure}[htbp]
\centering
\includegraphics[width=0.95\textwidth]{fig7}
\caption{双卡通信算子分解与暴露比例分析}
\label{fig:comm-op-breakdown}
\end{figure}

为更加准确的定位 FSDP 训练框架下的通信热点，进一步对双卡场景下
的通信算子进行了分解分析。如图 2-3 所示，取 GPT2-medium 的训练数据进
行分析，左侧饼图展示了双卡训练中通信算子的耗时占比：All-Gather 操作
占通信总耗时的 61.7\%，Reduce-Scatter 操作占 38.3\%；右侧饼图则量化了
通信与计算的重叠特性，其中暴露通信（Exposed/Blocking，即阻塞计算的通
信）占比 42.6\%，而可与计算重叠（Overlapped/Hidden）的通信占比 57.4\%。

尽管 All-Gather 的绝对耗时更长，但结合 FSDP 的反向传播机制与通信
暴露比例分析可发现：Reduce-Scatter 通常位于梯度计算完成后的
关键节点上，其执行直接阻塞后续计算步骤，阻塞效应更为显著；而
All-Gather 主要发生在前向传播和反向传播的参数获取阶段，其通信可以通
过预取（Prefetching）与计算重叠（Overlap）机制被掩盖，右侧饼图中 57.4\%
的重叠通信占比也印证了这一点。此外，从 FSDP 训练框架和优化可行性
角度看，All-Gather 传输的是模型权重，主要参与模型的前向传播阶段以及
后向传播时的梯度计算，对其进行有损压缩往往会引入较大的精度风险；而
Reduce-Scatter 传输的是梯度张量，其压缩空间更大且精度影响可控。因此，
本研究将后向传播之后的梯度张量传输环节作为通信压缩优化的主要目标。

\section{本章小结}

本章通过构建单卡与双卡GPT-2模型训练对比实验，利用PyTorch Profiler性能分析工具对FSDP分布式训练过程中的通信开销进行了量化分析。
实验结果表明：通信开销随模型规模增大而显著增长，在GPT2-large模型中通信占比已达61.2\%；
Reduce-Scatter操作位于反向传播关键路径上，是通信压缩优化的首要目标；
All-Gather通信可通过预取机制部分掩盖，而Reduce-Scatter的阻塞效应更为显著。
这些发现为后续通信压缩算法的设计提供了实验依据。
